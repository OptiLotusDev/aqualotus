# Aqualotus

Aqualotus is the visual programming environment for the **Optilotus** language.

- **Optilotus** — language and runtime (Rust, headless + WASM)
- **Aqualotus** — shared UI (TypeScript / React) that talks to Optilotus

This repository is a monorepo with **one shared React UI** for all platforms:

- **Web** — Vite dev server / static build (works now)
- **Desktop** — Tauri shell loading the same UI (Windows / macOS / Linux)
- **Mobile** — Capacitor shell loading the same UI (Android / iOS)

Mobile vs desktop differences are **layouts, not separate apps**.

---

## Project structure

```text
aqualotus/
├── crates/optilotus/      # Rust core (headless + WASM). No UI code.
├── apps/aqualotus-ui/     # ONE shared React UI
│   ├── src/layouts/       # DesktopLayout + MobileLayout
│   ├── src/components/    # Shared components (OptilotusPanel, …)
│   ├── src/lib/           # Optilotus WASM bridge
│   ├── src-tauri/         # Tauri desktop shell
│   ├── android/ ios/      # Capacitor mobile shells (generated)
│   └── ...
└── docs/                  # Roadmap and design documents
```

Important rules:
- Language and runtime logic live only in `crates/optilotus`.
- The UI must not redefine Optilotus behavior.
- The UI talks to Optilotus through the WASM bridge.

## Prerequisites

- [Rust](https://rustup.rs/) (stable)
- Node.js 20+
- `wasm-pack`:
  ```bash
  cargo install wasm-pack
  ```
- Browser for the web UI
- Desktop (Tauri): OS webview dependencies —
  [Tauri prerequisites](https://v2.tauri.app/start/prerequisites/).
  On Ubuntu/Debian for example:
  ```bash
  sudo apt install libwebkit2gtk-4.1-dev librsvg2-dev
  ```
- Mobile (Android): [Android Studio](https://developer.android.com/studio) + SDK
- Mobile (iOS): macOS + Xcode (iOS builds only work on macOS)

## First-time setup

```bash
git clone <repo-url>
cd aqualotus

# Rust checks
cargo test --workspace

# Frontend dependencies
cd apps/aqualotus-ui
npm install
```

## Daily commands

### Run the app (recommended)
From `apps/aqualotus-ui`:

```bash
npm run dev
```

This will:
1. Rebuild Optilotus WASM from the Rust crate
2. Start the Vite dev server

Then open the URL shown in the terminal (usually http://localhost:5173).

You should see the **Optilotus (WASM)** panel responding (version, health, etc.).

### Run UI only (no Rust rebuild)
When you only changed frontend code:

```bash
npm run dev:ui
```

### Rebuild WASM manually
```bash
npm run build:wasm
```

### Test Rust
From the repo root:

```bash
cargo test --workspace
```

### Production frontend build
```bash
cd apps/aqualotus-ui
npm run build
```

### Desktop (Tauri)
```bash
cd apps/aqualotus-ui
npm run tauri:dev     # dev window (rebuilds WASM first)
npm run tauri:build   # production bundle
```
Requires the Tauri OS dependencies from Prerequisites.

### Mobile (Capacitor)
```bash
cd apps/aqualotus-ui
npm run mobile:android  # sync + open Android Studio
npm run mobile:ios      # sync + open Xcode (macOS only)
```
On Linux, Android is the realistic target; iOS builds require macOS + Xcode.

## Workflow notes

- One UI codebase for all platforms — do not create a second app.
- Mobile vs desktop differences are **layouts** (`src/layouts/`), not separate apps.
- After changing Optilotus (Rust) APIs used by the UI → use commands that run `build:wasm`
  (`dev`, `build`, `tauri:dev`, `tauri:build`, `mobile:*` all do).
- After changing only React/UI code → `npm run dev:ui` is enough.
- Do not edit files under `apps/aqualotus-ui/src/wasm/` by hand; they are generated.
- The `android/` and `ios/` folders are generated by Capacitor; `src-tauri/` is the Tauri shell.
